# kividb_client_certificates (Data Source)

How a database checks client certificates (mutual TLS), and what is in the CA bundle it checks them against -- including when each CA expires, which is when every client certificate it signed stops being accepted.

Set the mode and the CA with `client_cert_mode` and `client_ca_pem` on `kividb_instance`; this reads them for a database that configuration does not manage, or to watch expiry.

```terraform
# How a database checks client certificates, and when its CA expires.
data "kividb_client_certificates" "payments" {
  instance_id = kividb_instance.payments.id
}

output "client_ca_expires" {
  value = [for c in data.kividb_client_certificates.payments.ca_certificates : "${c.subject}: ${c.not_after}"]
}
```

## Schema

### Required

- `instance_id` (String) A database in this organization.

### Read-Only

- `available` (Boolean) Whether this database can use client certificates at all. False for sharded databases.
- `ca_certificates` (List of Object) Each certificate in `ca_pem`: its `subject`, when it expires (`not_after`, RFC 3339) and its SHA-256 fingerprint (`fingerprint_sha256`). Empty when there is none. (see [below for nested schema](#nestedatt--ca_certificates))
- `ca_pem` (String) The CA bundle the database checks client certificates against, in PEM. Null when the mode is `off`.
- `id` (String) The database's id.
- `mode` (String) `off`, `optional` or `required`.
- `tls_enabled` (Boolean) Whether the database serves TLS, which client certificates need.
- `tls_only` (Boolean) Whether plaintext connections are refused, which `required` needs.
