# kividb_audit_log_settings (Data Source)

Whether the organization keeps an audit log, and for how long. Read with an API
key that has the owner or admin role.

```terraform
# Whether the organization keeps an audit log. Needs an owner or admin key.
data "kividb_audit_log_settings" "this" {}

# Turning the log on is the owner's decision, made signed in to the console, so
# Terraform cannot do it -- but it can refuse to go on without it.
resource "terraform_data" "require_audit_log" {
  lifecycle {
    precondition {
      condition     = data.kividb_audit_log_settings.this.enabled
      error_message = "Turn on the audit log (Dashboard → Settings → Audit log, as the owner) before applying."
    }
  }
}
```

## Why this is not a resource

Turning the audit log on or off is accepted only from the organization's owner,
signed in to the console (Dashboard → Settings → Audit log). The API refuses the
change from every API key, whatever its role: whether an organization keeps a
record of what its members do is the owner's decision, as a person. A resource
could only ever fail to apply, so the provider reads the setting instead — which
is enough to stop a plan on an organization that has the log off, as the example
does.

## What turning it off does

Turning the log off stops new events being recorded. It deletes nothing: events
already recorded stay in the console for `hot_days` and in the S3 Object Lock
archive for `retention_days`, and stay in the export. The log records its own
switching off, so it says when it stopped.

## Schema

### Read-Only

- `enabled` (Boolean) Whether actions in the organization are being recorded. Off until the owner turns it on.
- `enabled_at` (String) When it was last turned on. Null while it is off.
- `enabled_by` (String) The email of the owner who turned it on. Null while it is off.
- `hot_days` (Number) How many days of events the console and `GET /audit-log` show. Older events are moved to an S3 Object Lock archive and are still in the export.
- `retention_days` (Number) How many days an event is kept in all, archive included. Turning the log off stops new events being recorded; it does not delete or shorten the ones already kept.
