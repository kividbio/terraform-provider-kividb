# kividb_export_destination_verification (Resource)

Verifies a [`kividb_export_destination`](export_destination.md): KiviDB assumes
the role with the destination's external id, confirms the role is in the account
named, finds the bucket as owned by that account, and writes a small test file
under the prefix. A destination receives exports only once this has passed.

```terraform
resource "kividb_export_destination_verification" "backups" {
  destination_id = kividb_export_destination.backups.id

  # Verify again whenever the role's policies change.
  triggers = {
    trust      = aws_iam_role.kividb_exports.assume_role_policy
    permission = aws_iam_role_policy.kividb_exports.policy
  }

  # After the role and its policy exist; IAM may still take a minute to make
  # the role assumable, and the check is retried for up to five minutes.
  depends_on = [aws_iam_role_policy.kividb_exports]
}
```

## When verification fails

IAM takes a little while to make a new role assumable, so a verification that
does not pass is retried, every ten seconds for up to five minutes. If it still
does not pass, the apply fails with the API's reason and the step it stopped at
— `assume_role`, `session_account`, `bucket` or `write` — and nothing is
recorded for this resource.

Nothing is orphaned by that. The destination is in state as its own resource,
and after a refresh reads `status = "failed"` with the same reason in
`last_error`. Fix the role or the bucket and apply again: the verification runs
afresh.

## Staying verified

A destination verified again in the console that fails (its role was changed,
say) is no longer verified. Refreshing this resource then removes it from
state, so the next plan verifies again rather than reporting a destination that
no longer receives anything as fine. Use `triggers` to verify again whenever the
role's policies change.

Destroying this resource changes nothing in KiviDB: there is no un-verifying a
destination. Destroy the destination to stop deliveries.

## Schema

### Required

- `destination_id` (String) The `id` of the `kividb_export_destination` to verify.

### Optional

- `triggers` (Map of String) Any values that should make Terraform verify again when they change -- the role's policies, for example. Changing one replaces this resource, which verifies afresh.

### Read-Only

- `bucket_region` (String) The bucket's region, as verification found it.
- `id` (String) The destination's id.
- `status` (String) `verified`. A destination that is no longer verified is removed from state, so the next plan verifies it again.
- `verified_at` (String) When the destination passed verification.

## Import

Import is supported using the following syntax:

```shell
# A verification is imported by its destination's id. Only a destination that
# is verified now can be imported.
terraform import kividb_export_destination_verification.backups 3e7a1c2b-4d5f-4a6b-8c9d-0e1f2a3b4c5d
```
