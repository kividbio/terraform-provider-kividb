# kividb_snapshot_schedule (Resource)

Automatic disk snapshots of a database, taken on a schedule and expired by a
retention rule.

Each scheduled snapshot is the same kind of copy a `kividb_disk_snapshot` is,
and is billed the same way, by the gigabyte-month it is kept; retention is
what bounds that. Only snapshots the schedule took are ever expired by it: one
taken by hand, in the console or with `kividb_disk_snapshot`, is kept until it
is deleted.

Snapshots are taken while the database is running. Free-tier and sharded
databases are not snapshotted on a schedule, so the setting is stored for them
but has no effect -- the apply says so.

**Deleting this resource turns the schedule off and leaves its retention as
it is.** Putting the default retention back could expire scheduled snapshots
already taken -- the default keeps the last 5 -- so the ones the schedule
holds stay under the rule they were taken with.

```terraform
# A disk snapshot every day, keeping the newest seven.
resource "kividb_snapshot_schedule" "cache" {
  instance_id    = kividb_instance.cache.id
  cadence        = "daily"
  retention_mode = "keep_last"
  retention      = 7
}

# Hourly snapshots of a busier database, each kept for two days.
resource "kividb_snapshot_schedule" "orders" {
  instance_id    = kividb_instance.orders.id
  cadence        = "hourly"
  retention_mode = "keep_days"
  retention      = 2
}
```

## Schema

### Required

- `instance_id` (String) The database to snapshot. **Changing this turns the old database's schedule off and sets the new one's.**

### Optional

- `cadence` (String) How often: `hourly`, `daily` (the default) or `weekly`.
- `enabled` (Boolean) Take snapshots. Defaults to `true`; `false` stops new ones and keeps those already taken under `retention`.
- `retention` (Number) Snapshots to keep (`keep_last`) or days to keep each one (`keep_days`), 1-365. Defaults to 5.
- `retention_mode` (String) How `retention` is counted: `keep_last` (the default) keeps that many of the newest scheduled snapshots; `keep_days` keeps each for that many days. Changing either applies to the snapshots already held, so shortening it expires some at once -- and an expired snapshot cannot be recovered.

### Read-Only

- `id` (String) The database's id: a database has one schedule.
