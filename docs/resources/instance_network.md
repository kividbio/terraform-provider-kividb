# kividb_instance_network (Resource)

Which addresses may connect to a database over its public endpoint: the
allowlist, applied to the database's firewall (a security group, network
security group or firewall rule, depending on the cloud).

The allowlist is the whole list. Applying this resource replaces whatever the
database had -- including the address KiviDB added for whoever created it -- so
list every address that needs to connect. An empty allowlist lets no client in
over the public endpoint; the plan warns about it.

Two settings that share this endpoint are kept where they belong instead:
`tls_only` on `kividb_instance`, because it is tied to the database's TLS and
client-certificate settings, and blocking public access on
`kividb_private_link`, because it needs private connectivity to exist. This
resource never changes either.

**Destroying this resource leaves the allowlist as it is**, and only stops
Terraform managing it. Both alternatives would change who can connect as a
side effect of removing configuration: an empty list locks every client out,
and an open one exposes the database to the internet.

```terraform
# Who may connect over the public endpoint. This is the whole list: anything
# not here -- including the address KiviDB added for whoever created the
# database -- loses access when it is applied.
resource "kividb_instance_network" "orders" {
  instance_id = kividb_instance.orders.id

  allowlist = [
    { cidr = "203.0.113.0/24", label = "office" },
    { cidr = "198.51.100.17/32", label = "ci runner" },
  ]
}

output "connect_on" {
  value = kividb_instance_network.orders.port
}
```

## Schema

### Required

- `allowlist` (Attributes Set) The addresses allowed to connect, at most 20. Each is an IPv4 `cidr` with its prefix, such as `203.0.113.7/32` for one address, and an optional `label`. `0.0.0.0/0` allows any address; the password is then the only thing in the way. (see [below for nested schema](#nestedatt--allowlist))
- `instance_id` (String) The database. **Changing this sets the new database's allowlist and leaves the old one's as it is.**

### Read-Only

- `id` (String) The database's id: a database has one allowlist.
- `port` (Number) The port clients connect to: 6379, or 6380 when the database is TLS-only. 0 while public access is blocked.
- `ports` (List of Number) Every port the allowlist is open on: both 6379 and 6380 when TLS is on but not required.
- `sync_error` (String) Why the firewall does not match yet, when `synced` is false.
- `synced` (Boolean) Whether the database's firewall matches the allowlist. False for a moment while a database is still being created; the allowlist is applied once it is.

### Nested Schema for `allowlist`

Required:

- `cidr` (String) An IPv4 address range, e.g. `203.0.113.0/24`. Written with its prefix and without leading zeros, as the API stores it.

Optional:

- `label` (String) What the address is, up to 64 characters, e.g. `office` or `ci runners`.
