# kividb_semantic_cache (Resource)

A semantic cache namespace on a database: a place to store an LLM's answer to a
prompt and find it again for a prompt that means the same thing.

```terraform
# Your application sends its own embedding with every write and lookup, so
# KiviDB never calls a model and holds no provider key.
resource "kividb_semantic_cache" "answers" {
  instance_id    = kividb_instance.cache.id
  name           = "answers"
  embed_provider = "none"
  dimensions     = 384
}

# Or let KiviDB embed the prompt with OpenAI, using your key.
resource "kividb_semantic_cache" "support" {
  instance_id         = kividb_instance.cache.id
  name                = "support"
  embed_provider      = "openai"
  embed_model         = "text-embedding-3-small"
  embed_api_key       = var.openai_api_key
  dimensions          = 1536
  threshold           = 0.7
  default_ttl_seconds = 3600
}

# Destroying either one deletes every entry cached in it.
```

## Destroying deletes the cache

The entries live in the database itself, under keys beginning
`kividb:semcache:{<name>}:`. Destroying the resource deletes every entry cached
in the namespace, and so does anything that replaces it: a different
`instance_id` or `name`. The database must be running for the delete to go
through; a stopped database refuses it, and the namespace stays in state.

Terraform manages the namespace's settings only. Your application writes and
looks up entries through the API (`POST .../semantic-cache/<name>/entries` and
`.../lookup`), or through the KiviDB MCP server.

## What changes in place

Everything except `instance_id` and `name` changes in place, with one condition:
`dimensions` can change only while the namespace is empty, because vectors of
two sizes cannot be compared. With entries in it the API refuses the change and
says how many there are. Empty the namespace first (Flush in the console, or
`POST .../semantic-cache/<name>/flush`), or replace the resource with
`terraform apply -replace=kividb_semantic_cache.<name>`, which deletes its
entries.

## Embedding providers

With `embed_provider = "none"` KiviDB never calls a model: your application
sends its own vector, `dimensions` long, with every write and lookup. With
`openai` or `openai_compatible` KiviDB embeds the prompt using your key, which
it stores encrypted and never returns. The key is therefore kept in state as
you gave it, and a key changed in the console is not detected. Leaving
`embed_api_key` out of a later apply keeps the stored key, as long as the
provider stays the same. Embedding calls bill your account with that provider.

`threshold` is computed when left out: the API uses 0.6 when the namespace is
created, and a later apply without it keeps whatever the namespace has.

## Schema

### Required

- `dimensions` (Number) The length of every vector in the namespace, 2-8192: what the model produces (1536 for `text-embedding-3-small` unless it is asked for fewer), or what your application sends with `none`. Changes in place only while the namespace is empty; with entries in it the API refuses, because vectors of two sizes cannot be compared.
- `embed_provider` (String) Where prompts are turned into vectors. `none`: your application sends its own vector with every write and lookup, and KiviDB never calls a model. `openai`: OpenAI's embeddings API, with your key. `openai_compatible`: any service with an OpenAI-style `/embeddings` endpoint at `embed_base_url`, with your key. The API calls this `provider`. Changes in place.
- `instance_id` (String) The database the namespace lives in. Changing it makes a new, empty namespace there and deletes this one with everything in it.
- `name` (String) The namespace's name, unique within the database: 1-63 lowercase letters, digits, `-` or `_`, starting with a letter or digit. A database holds at most 50 namespaces. Changing it makes a new, empty namespace and deletes this one with everything in it.

### Optional

- `default_ttl_seconds` (Number) How long an entry is kept when the write does not say, in seconds: 60 to 31536000 (a year). Defaults to 86400 (a day). Changes in place, for entries written afterwards.
- `embed_api_key` (String, Sensitive) Your API key for the embedding provider. Required to create a namespace with a provider other than `none`. KiviDB stores it encrypted and never returns it, so Terraform keeps the value you gave in state and cannot detect a key changed elsewhere. Leaving it out on a later apply keeps the stored key, as long as the provider stays the same.
- `embed_base_url` (String) For `openai_compatible` only, and required for it: the https URL its `/embeddings` sits under. Addresses on private or reserved networks are refused.
- `embed_model` (String) The embedding model, e.g. `text-embedding-3-small`. Required unless `embed_provider` is `none`, and not used when it is.
- `threshold` (Number) The cosine similarity a lookup must reach to count as a hit, above 0 and at most 1. The API uses 0.6 when the namespace is created without one, which catches rewordings with OpenAI's `text-embedding-3-small` while staying well above unrelated prompts; left out of the configuration afterwards, the current value is kept. A lookup may override it. Changes in place.

### Read-Only

- `created_at` (String) When the namespace was created.
- `has_embed_api_key` (Boolean) Whether KiviDB holds an API key for the provider.
- `id` (String) `<instance_id>/<name>`, which is also the import id.

## Import

Import is supported using the following syntax:

```shell
# Import a namespace by its database's id and its name. The provider's API key
# is never returned by the API, so set embed_api_key in the configuration again.
terraform import kividb_semantic_cache.answers 790df3ae-c064-45f5-b924-9ed89471fd72/answers
```
