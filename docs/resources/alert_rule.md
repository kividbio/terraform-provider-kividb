# kividb_alert_rule (Resource)

An alert: a condition on one database, or on the organization's credit, sent to
one or more [`kividb_alert_channel`](alert_channel.md)s.

```terraform
# Memory above 90% for ten minutes, to Slack and the owners.
resource "kividb_alert_rule" "memory" {
  name        = "cache memory above 90%"
  metric      = "memory_pct"
  instance_id = kividb_instance.cache.id
  op          = "gt"
  threshold   = 90
  for_minutes = 10
  channel_ids = [
    kividb_alert_channel.slack.id,
    kividb_alert_channel.owners.id,
  ]
}

# A failover fires on the event itself: no op, threshold or for_minutes.
resource "kividb_alert_rule" "failover" {
  name        = "cache failed over"
  metric      = "failover"
  instance_id = kividb_instance.cache.id
  channel_ids = [kividb_alert_channel.pagerduty.id]
}

# Credit runway is about the organization, so it names no database. Left unset,
# op and threshold take the metric's defaults: below 7 days.
resource "kividb_alert_rule" "credit" {
  name             = "credit running low"
  metric           = "credit_runway_days"
  cooldown_minutes = 1440
  channel_ids      = [kividb_alert_channel.owners.id]
}
```

## Metrics

| `metric`                  | About            | Unit    | Default condition |
|---------------------------|------------------|---------|-------------------|
| `memory_pct`              | a database       | %       | above 80          |
| `ops_per_sec`             | a database       | ops/s   | above 10000       |
| `latency_p99_ms`          | a database       | ms      | above 5           |
| `connected_clients`       | a database       | clients | above 1000        |
| `replication_lag_seconds` | a database       | s       | above 10          |
| `failover`                | a database       | —       | a replica was promoted |
| `credit_runway_days`      | the organization | days    | below 7           |

Every metric except `credit_runway_days` needs `instance_id`;
`credit_runway_days` must not have one. A `failover` alert fires on the event,
so it takes no `op`, `threshold` or `for_minutes`.

## When it is sent

The condition has to hold for `for_minutes` before the alert fires. It is sent
once when it fires, again every `cooldown_minutes` for as long as it keeps
firing, and once more when it clears.

Any change to an alert is applied in place and starts its condition over: an
alert that was firing is treated as new, and sends no resolved notice for the
condition it no longer has.

## Limits

An organization can have at most 100 alerts, each sending to at most 10
channels. An API key limited to some databases cannot manage alerts at all,
because an alert can name any database and send to any channel of the
organization; use a key without database limits.

Deleting the database an alert watches deletes the alert, and the next plan
creates it again — for a database that no longer exists, which the API refuses
until `instance_id` points somewhere real.

## Schema

### Required

- `channel_ids` (Set of String) Where to send it: 1 to 10 `kividb_alert_channel` ids. A channel an alert sends to cannot be deleted until the alert stops naming it.
- `metric` (String) What to watch, with its default condition when `op` and `threshold` are not set: `memory_pct` (memory used, %; above 80), `ops_per_sec` (operations per second; above 10000), `latency_p99_ms` (p99 command latency, ms; above 5), `connected_clients` (above 1000), `replication_lag_seconds` (above 10), `failover` (a replica was promoted -- fires on the event, so it takes no `op`, `threshold` or `for_minutes`) or `credit_runway_days` (days of credit left at the current rate; below 7 -- about the organization, so it takes no `instance_id`).
- `name` (String) A name for the alert, 1 to 80 characters. Each notice leads with it.

### Optional

- `cooldown_minutes` (Number) How long to wait before telling the channels again about an alert that is still firing, 5 to 10080 minutes (a week). Defaults to 60.
- `enabled` (Boolean) Whether the alert is evaluated. Defaults to true; set false to silence it without losing its configuration.
- `for_minutes` (Number) How long the condition has to hold before the alert fires, 0 to 1440 minutes. Defaults to 5. Not used by `failover`, which fires on the event.
- `instance_id` (String) The database the alert is about. Required for every metric except `credit_runway_days`, which is about the organization and must not have one. Deleting the database deletes its alerts, and Terraform then plans to create this one again.
- `op` (String) `gt` fires when the value is above `threshold`, `lt` when it is below. Defaults to the metric's usual direction (see `metric`). Not used by `failover`.
- `threshold` (Number) The value to compare against, in the metric's unit; zero or more. Defaults to the metric's default (see `metric`). Not used by `failover`.

### Read-Only

- `id` (String) Alert id.

## Import

Import is supported using the following syntax:

```shell
# Import an alert by its id, from the console (Dashboard → Settings → Alerts).
terraform import kividb_alert_rule.memory 6d2c9b1a-0f3e-4b7d-8a6c-5e4f3d2c1b0a
```
