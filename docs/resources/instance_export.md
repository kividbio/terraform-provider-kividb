# kividb_instance_export (Resource)

Where a database's KDB exports are delivered, and how often it exports on its
own. It is the database's export configuration, which always exists, so
creating this resource sets it and destroying it turns exports off. One per
database: two would overwrite each other.

```terraform
# Deliver the database's exports to your bucket, and export it every day.
resource "kividb_instance_export" "orders" {
  instance_id = kividb_instance.orders.id

  # The verification's id is the destination's id; referencing it, rather than
  # the destination, is what orders this after the destination is verified.
  export_destination_id = kividb_export_destination_verification.backups.id
  cadence               = "daily" # "off", "daily" or "weekly"
}
```

## Delivery

With `export_destination_id` set, every KDB export of the database — scheduled
ones, and those taken with [`kividb_kdb_snapshot`](kdb_snapshot.md), the
console or an assistant — is also copied into that bucket once it is written.
The destination must be verified; the API refuses one that is not. Reference
the [`kividb_export_destination_verification`](export_destination_verification.md)'s
`id` (which is the destination's id) so this is applied after verification
passes.

## Schedules

`cadence = "daily"` or `"weekly"` has the database export itself, and a
schedule needs a destination. KiviDB keeps its own copy of a scheduled export
for 7 days; the one in your bucket is yours to keep or expire.

Scheduled exports run only on a running, single-shard, paid database. A
schedule on a free-tier database is refused: at plan when the database already
exists, otherwise by the API at apply, in the same words. A destination with
`cadence = "off"` is accepted there, and an export taken on demand is still
delivered. The API refuses an export configuration for a sharded database.

## Schema

### Required

- `instance_id` (String) The database whose exports this configures.

### Optional

- `cadence` (String) How often the database exports on its own: `off`, `daily` or `weekly`. Defaults to `off`. A schedule needs `export_destination_id`. KiviDB keeps its own copy of a scheduled export for 7 days, since the bucket holds yours. A schedule on a free-tier database is refused (at plan, when the database already exists); scheduled exports do not run on sharded ones.
- `export_destination_id` (String) The `kividb_export_destination` to deliver to. It must be verified, so reference the `kividb_export_destination_verification`'s `id` (or depend on it) rather than the destination's, or the API refuses a destination that has not passed yet. Unset, exports stay in KiviDB's storage only.

### Read-Only

- `id` (String) The database's id.

## Import

Import is supported using the following syntax:

```shell
# A database's export configuration is imported by the database's id.
terraform import kividb_instance_export.orders 790df3ae-c064-45f5-b924-9ed89471fd72
```
