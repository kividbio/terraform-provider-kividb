# kividb_disk_snapshot (Resource)

A point-in-time copy of a database's data volume.

```terraform
resource "kividb_disk_snapshot" "before_migration" {
  instance_id = kividb_instance.cache.id
  label       = "before-migration"
}

# The label is the only thing about a snapshot you can change afterwards.
# Pointing instance_id at a different database plans a new snapshot and destroys
# this one: nothing re-points a copy that has already been taken.
```

## What it is for

A snapshot in configuration is a snapshot you can point at — the deliberate,
named copy taken before something irreversible, with Terraform enforcing the
ordering:

```hcl
resource "kividb_disk_snapshot" "pre_resize" {
  instance_id = kividb_instance.cache.id
  label       = "pre-resize"
}

resource "kividb_instance" "cache" {
  # ...
  depends_on = [kividb_disk_snapshot.pre_resize]
}
```

This is not a backup schedule. For routine recurring copies use scheduled
snapshots, which run without an apply and are retained by policy.

## Pointing it elsewhere replaces it

`instance_id` forces replacement: nothing re-points a copy already taken.
Changing it plans a new snapshot and destroys the old one, which deletes a
restore point. `label` is the exception and changes in place.

## Waiting

The apply waits for the copy to finish by default, because a snapshot still
being written cannot be restored from. Set `wait_for_ready = false` to return as
soon as the server accepts it.

## Restoring

Restoring into an existing database is not a Terraform operation. It replaces
the contents of a running database — something you do deliberately and watch,
not something a plan performs because a file changed. Restore from the console
or through an assistant.

Creating a *new* database from a snapshot is: set
[`kividb_instance`](instance.md)'s `restore_from_snapshot_id` to the snapshot's
`id`.

## Where a snapshot lives

A snapshot is stored where its database runs — the same `cloud`, `region` and
cloud account (`cloud_account_id`, null for KiviDB's cloud) — and is restored
only there. A database created from it must be in that cloud, region and
account; anything else is refused.

## Schema

### Required

- `instance_id` (String) The database to snapshot.

### Optional

- `label` (String) A name for the snapshot. The server generates one when this is not set, which is why it is also computed.
- `wait_for_ready` (Boolean) Wait for the volume copy to finish before the apply returns. Defaults to true, because a snapshot still being written cannot be restored from, and an apply that returned success would be saying otherwise.

### Read-Only

- `cloud` (String) Cloud the snapshot is stored in.
- `cloud_account_id` (String) The cloud account the snapshot is stored in: the database's own. Null for a snapshot in KiviDB's cloud. A database made from this snapshot (`kividb_instance.restore_from_snapshot_id`) is placed in this account, and in the snapshot's `cloud` and `region`.
- `cloud_account_name` (String) The name of that cloud account, as the KiviDB console shows it. Null for a snapshot in KiviDB's cloud.
- `created_at` (String) When the snapshot was requested.
- `id` (String) Snapshot id.
- `instance_name` (String) Name the database had when the snapshot was taken.
- `region` (String) Region the snapshot is stored in.
- `size_gb` (Number) Size of the captured volume, once the copy reports one.
- `status` (String) Snapshot state as the server reports it.
