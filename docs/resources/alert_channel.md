# kividb_alert_channel (Resource)

Where alerts are delivered: email to the organization's members, a Slack or
Microsoft Teams channel, a PagerDuty service, or a signed webhook. A
[`kividb_alert_rule`](alert_rule.md) sends to one or more channels.

```terraform
# The organization's owners and admins, by email. An email channel sends only to
# the organization's own members, chosen by role, never to an address you type.
resource "kividb_alert_channel" "owners" {
  name  = "Owners and admins"
  kind  = "email"
  roles = ["owner", "admin"]

  # A channel cannot be edited, only replaced, and a channel an alert still
  # sends to cannot be deleted. This lets the alert move to the new channel
  # before the old one goes.
  lifecycle {
    create_before_destroy = true
  }
}

variable "slack_webhook_url" {
  type      = string
  sensitive = true
}

resource "kividb_alert_channel" "slack" {
  name = "#ops-alerts"
  kind = "slack"
  url  = var.slack_webhook_url

  lifecycle {
    create_before_destroy = true
  }
}

variable "pagerduty_integration_key" {
  type      = string
  sensitive = true
}

resource "kividb_alert_channel" "pagerduty" {
  name        = "Database on-call"
  kind        = "pagerduty"
  routing_key = var.pagerduty_integration_key
  region      = "us"

  lifecycle {
    create_before_destroy = true
  }
}

# A signed webhook. The signing secret is shown once, when the channel is
# created, and kept in state for you to hand to the receiver.
resource "kividb_alert_channel" "webhook" {
  name = "Incident bridge"
  kind = "webhook"
  url  = "https://hooks.example.com/kividb"

  lifecycle {
    create_before_destroy = true
  }
}

output "webhook_signing_secret" {
  value     = kividb_alert_channel.webhook.signing_secret
  sensitive = true
}
```

## Kinds

| `kind`      | Takes                     | Delivers to |
|-------------|---------------------------|-------------|
| `email`     | `roles`                   | The organization's members with those roles (default owners and admins). Never an address you type, so an alert cannot be used to mail somebody outside the organization. |
| `slack`     | `url`                     | A Slack incoming webhook, `https://hooks.slack.com/services/...`. |
| `teams`     | `url`                     | A Teams Workflows webhook (`logic.azure.com`, `api.powerplatform.com`) or an Office 365 connector (`webhook.office.com`). |
| `pagerduty` | `routing_key`, `region`   | An Events API v2 integration on a PagerDuty service, in the `us` or `eu` service region. |
| `webhook`   | `url`                     | Any https URL on a public address, as a signed JSON POST. |

An organization can have at most 20 channels.

## A channel is replaced, never edited

The API has no way to change a channel once it exists. Changing any argument
plans a new channel and destroys the old one — and a channel that an alert
still sends to cannot be destroyed (`channel_in_use`). Give every channel

```hcl
lifecycle {
  create_before_destroy = true
}
```

so Terraform creates the new channel, moves the alerts to it, and only then
removes the old one.

## Secrets

`url` and `routing_key` are sensitive: whoever holds a Slack or Teams webhook
URL can post to that channel, and whoever holds a PagerDuty integration key can
open incidents. The API stores them sealed and never returns them; it shows
`url_hint` (the URL's origin and the start of its path) or `key_hint` (the
key's last four characters) instead.

A webhook's `signing_secret` is shown once, by the request that creates the
channel, and kept in Terraform state. Each delivery carries

```
X-KiviDB-Signature: t=<unix seconds>,v1=<hex HMAC-SHA256 of "<t>.<body>">
```

computed with it. State holding these values should be stored as a secret.

## Testing a channel

There is no Terraform action for the console's **Send test** button. A test is
a notice sent now, not configuration, and the API allows one every 30 seconds
per channel; send it from the console (Dashboard → Settings → Alerts).

## Schema

### Required

- `kind` (String) How the notice is delivered: `email`, `slack`, `teams`, `pagerduty` or `webhook`. `email` takes `roles`; `slack`, `teams` and `webhook` take `url`; `pagerduty` takes `routing_key` and `region`.
- `name` (String) A name for the channel, 1 to 80 characters, as the console and each notice show it.

### Optional

- `region` (String) For `pagerduty`: the PagerDuty service region, `us` or `eu`. Defaults to `us`; a PagerDuty account in the EU service region needs `eu`. Null for other kinds.
- `roles` (Set of String) For `email`: which of the organization's members receive it, by role -- any of `owner`, `admin` and `member`. Defaults to owners and admins. An email channel sends only to the organization's own members, never to an address you type, so an alert cannot be used to mail somebody outside it. Null for other kinds.
- `routing_key` (String, Sensitive) For `pagerduty`: the 32-character Integration Key of an Events API v2 integration on the PagerDuty service. Anyone holding it can open incidents on that service, so the API keeps it sealed and returns only its last four characters, `key_hint`.
- `url` (String, Sensitive) For `slack`, `teams` and `webhook`: where to post. Sensitive, because whoever holds a Slack or Teams webhook URL can post to that channel; the API never returns it whole, only `url_hint`. For `slack`, a Slack incoming-webhook URL (`https://hooks.slack.com/services/...`); for `teams`, a Teams Workflows webhook URL (on `logic.azure.com` or `api.powerplatform.com`) or an Office 365 connector URL (on `webhook.office.com`), over https; for `webhook`, any https URL up to 2048 characters on a public address, to which each notice is POSTed as JSON signed with `signing_secret`.

### Read-Only

- `created_at` (String) When the channel was created.
- `id` (String) Channel id. This is what `kividb_alert_rule.channel_ids` takes.
- `key_hint` (String) The PagerDuty key as the API shows it: its last four characters. Null for other kinds.
- `signing_secret` (String, Sensitive) For `webhook`: the secret each delivery is signed with. The header is `X-KiviDB-Signature: t=<unix seconds>,v1=<hex HMAC-SHA256 of "<t>.<body>">`. The API shows it once, in the response that creates the channel, and Terraform keeps that copy in state -- so treat the state as a secret. Null for other kinds, and null after an import, because there is no way to read it again; replace the channel to get a new one.
- `url_hint` (String) The URL as the API shows it: its origin and the start of its path. Enough to tell channels apart, not enough to post to one. Null for `email` and `pagerduty`.

## Import

Import is supported using the following syntax:

```shell
# Import a channel by its id, from the console (Dashboard → Settings → Alerts).
# The API never returns a channel's URL or PagerDuty key, so write it into the
# configuration afterwards: when it matches the channel's url_hint or key_hint
# it is recorded in place, and anything else replaces the channel. A webhook's
# signing secret cannot be read again and stays null after an import.
terraform import kividb_alert_channel.slack 3b1f6a0e-6c55-4a8e-9c1d-2f8e7b6a5d41
```
