# kividb_maintenance_window (Resource)

When KiviDB may do planned maintenance on a database: a weekly window,
four hours long, starting at a given hour on a given day in a given time zone.

Planned maintenance is work KiviDB starts on its own -- today, renewing the
database's TLS certificate, which restarts each node for a few seconds. It is
announced to the organization's owners at least 48 hours ahead and done inside
this window. Changes you make, failovers and the recovery of a failed node do
not wait for it.

Every database has a window from the start: Sunday 03:00 UTC unless it is
changed. This resource sets it. **Deleting this resource puts the window back to
Sunday 03:00 UTC** rather than leaving it where it was, because a window always
exists and that is the one a database without configuration has. Moving the
window, either way, moves maintenance already planned into the new one, with
fresh notice.

The day and hour are in `timezone`, so a window at 03:00 in Europe/Berlin stays
at 03:00 local time across daylight-saving changes.

```terraform
# Planned maintenance on Tuesdays from 02:00 to 06:00, Berlin time -- after
# the overnight batch jobs and before the working day.
resource "kividb_maintenance_window" "cache" {
  instance_id = kividb_instance.cache.id
  day         = "tuesday"
  hour        = 2
  timezone    = "Europe/Berlin"
}

# When the next window opens, and what KiviDB has planned for it.
output "next_maintenance" {
  value = kividb_maintenance_window.cache.next_window_start
}
```

## Schema

### Required

- `day` (String) The day the window starts on, in `timezone`: `sunday`, `monday`, ... `saturday`.
- `hour` (Number) The hour the window starts at, 0-23, in `timezone`. The window lasts four hours from it.
- `instance_id` (String) The database whose window this is. **Changing this resets the old database's window and sets the new one's.**

### Optional

- `timezone` (String) An IANA time zone such as `Europe/Berlin` or `Asia/Kolkata`. Defaults to `UTC`. The API checks the name and refuses one it does not know.

### Read-Only

- `description` (String) The window as the console shows it, e.g. `Sunday 03:00-07:00 (UTC)`.
- `id` (String) The database's id: a database has one window.
- `length_hours` (Number) How long the window lasts.
- `next_window_start` (String) When the next window starts, in UTC (RFC 3339). Moves on as each window passes.
- `notice_hours` (Number) The least notice given before planned maintenance.
- `planned` (List of Object) Maintenance KiviDB has planned: `kind` (e.g. `tls_certificate_renewal`), `starts_at`, and `restarts_nodes`. Empty when nothing is planned. (see [below for nested schema](#nestedatt--planned))
