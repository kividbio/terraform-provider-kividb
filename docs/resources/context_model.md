# kividb_context_model (Resource)

A Context Retriever model: a description of the records already in a database
that KiviDB turns into search indexes and into tools an AI agent calls over the
Model Context Protocol, with a [`kividb_context_agent_key`](context_agent_key.md).

```terraform
# Customers stored as hashes under customer:<id>, and their orders as JSON under
# order:<id>. The model indexes them and gives an agent tools to search each
# and to follow a customer to their orders.
resource "kividb_context_model" "shop" {
  instance_id = kividb_instance.cache.id
  name        = "shop"
  description = "The shop's customers and their orders."

  entities = [
    {
      name        = "customer"
      description = "A customer of the shop."
      prefix      = "customer:"
      fields = [
        { name = "name", type = "text", description = "Full name" },
        { name = "tenant", type = "tag" },
        { name = "plan", type = "tag" },
      ]
      relationships = [
        { name = "orders", entity = "order", field = "customer_id" },
      ]
    },
    {
      name        = "order"
      description = "An order a customer placed."
      prefix      = "order:"
      storage     = "json"
      id_field    = "order_id"
      fields = [
        { name = "customer_id", type = "tag" },
        { name = "total", type = "numeric", description = "Order total in cents" },
      ]
    },
  ]
}

# Destroying the model deletes its indexes and revokes its agent keys. The
# customer: and order: records stay in the database.
```

## Entities are nested attributes

The model's entities, their fields and their relationships are written as
nested attributes rather than as one `jsonencode()`d string. A plan then names
what changed (`entities[1].fields[2].type`) instead of showing two blocks of
JSON, the API's defaults (`storage`, `id_field`, `relationships`) appear as
values rather than as a difference against what the server stored, and names,
types and lengths are checked at plan time.

A relationship's `entity` must be another entity of this model, and its `field`
a `tag` or `numeric` field (or the `id_field`) of that entity. The API checks
that when the model is saved, and refuses it, naming the relationship, if not.

## Saving rebuilds the indexes

Every apply that creates or changes the model rebuilds its search indexes in the
database, which must be running. If the model is saved but the indexes cannot
be built, the apply fails with the API's reason. On a create the model is kept
in state, marked tainted, and replaced on the next apply.

## Destroying

Destroying the model deletes it, its search indexes and every agent key made
for it, so agents using those keys are refused at once. The records the model
described stay in the database. Changing `name` or `instance_id` replaces the
model, with the same effect on its keys; the API does not move a model to
another database.

Context models are not available on sharded databases. An organization has at
most 20.

## Schema

### Required

- `entities` (Attributes List) The kinds of record, 1-20, each with different names. Changes in place, and the indexes are rebuilt. (see [below for nested schema](#nestedatt--entities))
- `instance_id` (String) The database whose records the model describes. The API does not move a model to another database, so changing this replaces the model, which revokes its agent keys.
- `name` (String) The model's name, unique within the organization: 1-63 lowercase letters, digits, `-` or `_`, starting with a letter or digit. An organization has at most 20 models. Changing it replaces the model, which revokes its agent keys.

### Optional

- `description` (String) What the data is, for the agent: it is sent as the MCP server's instructions. Up to 2000 characters. Changes in place.

### Read-Only

- `created_at` (String) When the model was created.
- `id` (String) The model's name, which is also the import id.
- `mcp_url` (String) Where an agent connects over the Model Context Protocol (JSON-RPC over HTTP POST), sending one of this model's agent keys as `Authorization: Bearer kvctx_...`. The key names the model, so the URL is the same for every model.
- `tools` (List of String) The names of the tools the model gives an agent with full access. A key limited to some entities sees only theirs.

<a id="nestedatt--entities"></a>
### Nested Schema for `entities`

Required:

- `description` (String) What it is, in a sentence, 5-1000 characters: the agent reads this to decide which tool to call.
- `fields` (Attributes List) The fields to index, 1-50, each with a different name. (see [below for nested schema](#nestedatt--entities--fields))
- `name` (String) The entity's name, e.g. `customer`: 1-32 lowercase letters, digits and `_`, starting with a letter. It names the agent's tools.
- `prefix` (String) The key prefix every record of this entity has, e.g. `customer:`. Up to 100 characters, with no spaces or `*`, `?`, `[`, `]`.

Optional:

- `id_field` (String) The field holding the record's id, indexed as a tag so a record can be fetched by it. Defaults to `id`.
- `relationships` (Attributes List) Up to 10 links to other entities of this model, which become tools that follow them (a customer's orders). (see [below for nested schema](#nestedatt--entities--relationships))
- `storage` (String) How each record is stored: `hash` (the default) or `json`.

<a id="nestedatt--entities--fields"></a>
### Nested Schema for `entities.fields`

Required:

- `name` (String) The field's name in the record: 1-64 letters, digits and `_`, starting with a letter or `_`.
- `type` (String) `text`: searched by its words. `tag`: matched exactly (ids, statuses, tenants). `numeric`: compared and ranged.

Optional:

- `description` (String) What the field holds, for the agent. Up to 500 characters.


<a id="nestedatt--entities--relationships"></a>
### Nested Schema for `entities.relationships`

Required:

- `entity` (String) The related entity, by its `name` in this model.
- `field` (String) The field on the related entity that holds this entity's id: for customer to orders, the orders' `customer_id`. It must be a `tag` or `numeric` field of that entity, or its `id_field`.
- `name` (String) The relationship's name, e.g. `orders`: 1-32 lowercase letters, digits and `_`, starting with a letter.

Optional:

- `description` (String) What the link means, for the agent. Up to 500 characters.

## Import

Import is supported using the following syntax:

```shell
# Import a context model by its name.
terraform import kividb_context_model.shop shop
```
