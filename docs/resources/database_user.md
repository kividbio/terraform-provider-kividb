# kividb_database_user (Resource)

A user on one database, with its own password and a permission profile.

Every database comes with a default user (`kividbapp`), whose password is in the
console. Users made here are in addition to it, so an application can be given
only what it needs -- read-only for a reporting job, publish/subscribe for a
notifier -- and its password changed or revoked without touching anyone else's.

### Passwords

Set `password` to choose one, or leave it out and the API generates one (48
hexadecimal characters). Either way it is stored in Terraform state, so treat
the state as a secret. To change a generated password, change
`rotation_trigger` to any new value; to change a chosen one, change `password`.
A password changed in the console shows up as drift on the next plan: a chosen
one is set back, a generated one is read into state.

### When it takes effect

The API stores the user at once and applies it to the database's nodes in the
background, normally within a few seconds of the apply finishing. Users can
only be added, changed or removed while the database is running; an apply that
reaches a database still being created or changed waits for it, for up to 15
minutes.

Deleting this resource deletes the user, and connections using it are refused
from then on.

```terraform
# A read-only user for a reporting job. No password is set, so the API
# generates one; it is in state, so keep the state somewhere private.
resource "kividb_database_user" "reporting" {
  instance_id = kividb_instance.cache.id
  username    = "reporting"
  profile     = "read_only"
}

# A user whose password you choose -- from a secret store, not a literal.
resource "kividb_database_user" "notifier" {
  instance_id = kividb_instance.cache.id
  username    = "notifier"
  profile     = "pubsub"
  password    = var.notifier_password
}

# Rotate a generated password every month: changing rotation_trigger has the
# API generate a new one on the next apply.
resource "kividb_database_user" "worker" {
  instance_id      = kividb_instance.cache.id
  username         = "worker"
  rotation_trigger = "2026-10"
}

output "reporting_password" {
  value     = kividb_database_user.reporting.password
  sensitive = true
}
```

## Schema

### Required

- `instance_id` (String) The database the user belongs to. **Changing this creates the user on the other database and deletes it here.**
- `username` (String) 2-32 characters: lower-case letters, digits and underscores, starting with a letter. `kividbapp`, `kividb_system` and `kividb_internal` are KiviDB's own. A user cannot be renamed, so **changing this replaces the user**, and its password with it.

### Optional

- `password` (String, Sensitive) The user's password, 12-128 characters. Leave it out to have the API generate one, which is then readable here. Changed in place.
- `profile` (String) What the user may do: `read_write` (every data command), `read_only` (reads only) or `pubsub` (publish and subscribe only). Changed in place.
- `rotation_trigger` (String) Any value; changing it has the API generate a new password. Only used while `password` is not set -- a chosen password changes when `password` does. A date, or a `time_rotating` resource's id, makes a regular rotation.

### Read-Only

- `created_at` (String) When the user was created.
- `id` (String) `<instance_id>/<username>`, which is also the import id.

## Import

Import is supported using the following syntax:

```shell
# Import a user by its database's id and its username, separated by a slash.
terraform import kividb_database_user.reporting 790df3ae-c064-45f5-b924-9ed89471fd72/reporting
```
